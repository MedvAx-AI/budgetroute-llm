# Free-Colab Routing Study Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Repair the measurements that undermine quality-constrained routing and deliver an actually executed, reproducible 200-question free-Colab feasibility pilot.

**Architecture:** Extend the existing typed schemas, training, inference, cache, and evaluation paths; preserve their legacy defaults where scientifically defensible. Add one shared semantic feature path and a small pilot orchestrator, with a notebook calling repository functions rather than reimplementing them. Keep final confirmation disabled pending a separately frozen protocol.

**Tech Stack:** Python 3.11–3.13, Pydantic, NumPy, existing scikit-learn/joblib and Transformers/PyTorch extras, pytest, GitHub Actions, free Google Colab, existing MiniLM/FAISS integrations. No additional evaluation framework or paid provider.

**Spec:** [Approved design](../specs/2026-10-21-colab-routing-study-design.md). Specification and plan approved on 2026-10-21; Native execution selected. Implementation is in progress in an isolated checkout.

## Global Constraints

- Free Colab only: no subscription, paid GPU, commercial API, account creation, external public service, tunnels, or quota circumvention.
- Use the in-app browser for Colab; no native computer/desktop automation, local GPU inference, or local execution presented as remote testing.
- Keep normal tests offline and optional model dependencies lazy. Existing backend/policy/artifact boundaries and Windows support remain intact.
- Preserve historical Qwen2.5 reports/configurations unchanged. Do not publish agent instructions, local execution scratch, secrets, weights, or raw downloaded datasets.
- Pilot: 200 new development-only MMLU questions, seed 20261021, 120 fitting / 40 selection / 40 diagnostic; exclude the original 500 and normalized duplicate groups.
- Modern pair: Qwen3.5-0.8B/4B; named feasibility fallback: Qwen3-0.6B/4B-Instruct-2507. Explicit non-thinking, greedy, FP16, 64 output tokens, no quantization/compilation, batch/concurrency 1 initially.
- Later confirmation targets remain latency ratio <0.80 and accuracy difference >-0.02, with one-sided error allocation 0.025 per endpoint. The pilot cannot establish them.
- This plan is the tracked execution record. Keep task checkboxes, decisions, verification evidence, and final unfinished work here; leave the repository's ignored `docs/exec-plans/` scratch and local AGENTS/PLANS files unpublished.

## Review Focus

1. Probability exactly 1.0 or a configured threshold override must not reopen a new artifact explicitly marked infeasible; Task 1 tests this in learned and single/batch cascade execution.
2. Legacy artifacts and missing confidence/usage must remain readable without manufacturing calibration or zero cost; Tasks 1, 2, and 4 pin this behavior.
3. Prompt/template/runtime changes and interrupted resume must not reuse stale model outcomes or duplicate completed questions; Tasks 3 and 9 test identity and checkpoint boundaries.
4. Failed answers, unequal groups, and repeated IDs must not disappear or inflate the independent sample count; Task 5 tests denominator/alignment semantics.
5. A new seed, renamed dataset, fake component, or successful exit code must not masquerade as independent data or real remote evidence; Tasks 6, 9, and 10 assert provenance/content and artifact status.

## File and dependency map

Tasks 1–5 repair existing paths. Task 6 adds `experiments/pilot_data.py` for immutable selection/splits and a derived historical-exclusion manifest. Task 7 adds `features/semantic.py` for shared learned-gate inputs. Task 8 extends the existing Transformers backend, without a new backend framework. Task 9 adds `experiments/pilot.py`, `validation/colab.py`, a thin notebook, and real-pilot configurations. Task 10 executes off-local verification and publishes an evidence-based pilot card.

New tests live alongside current unit/integration tests. Existing `reporting/{markdown,tables,plots}.py` consumers must render nullable metrics as unavailable, not fail or replace them with zero. Documentation changes belong to the task whose behavior changes, with README/roadmap/changelog summaries kept current.

Dependency order: 1 → 2; 3 → 8; 2+4+5+6 → 7; all 1–8 → 9 → 10. Work may be reviewed independently, but integration uses this order to minimize shared-schema conflicts.
